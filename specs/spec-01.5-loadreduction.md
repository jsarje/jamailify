# Safeguards Against Duplicate Syncs and Load Reduction
This document outlines the specific mechanisms implemented when retrieving emails and syncing to prevent duplicate email synchronizations and minimize load on both source email servers and the Gmail API. These mechanisms work in conjunction with the application's core sync logic and database tracking to ensure efficient and reliable email synchronization.

## Email Retrieval - Unique Message Identification and Load Reduction
The pop3.go package provides the client for interacting with POP3 servers. It incorporates features to uniquely identify messages and reduce the amount of data transferred, thereby minimizing load.

1. Unique Message Identification (UIDs)
Mechanism: POP3 Unique Identifiers (UIDs)
Description: The POP3 protocol provides a UIDL (Unique ID Listing) command, which assigns a stable, unique identifier to each message on the server. The pop3.Client leverages this command to retrieve these UIDs.
Functions:
ListMessages(): This method retrieves a list of MessageInfo structs, each containing a SeqNum (sequence number) and a UID. The UID is a persistent identifier for a message, which remains constant even if the message's sequence number changes (e.g., due to other messages being deleted).
UIDLForSeq(seqNum int): This function allows for fetching the UID associated with a specific message sequence number. It includes a fallback mechanism to retrieve the full UIDL map if a direct UIDL query for a single sequence number fails.
Benefit: By consistently using and tracking these UIDs (which the main application logic stores in its SQLite database), the system can reliably determine if a message has already been processed. This prevents re-downloading and re-pushing messages that have already been synced.
2. Header-Only Fetching (TopMessage)
Mechanism: POP3 TOP command.
Description: The TopMessage(seqNum int) function allows the application to retrieve only the headers of an email message, without downloading the entire message body. The POP3 TOP command is designed for this purpose.
Benefit: This significantly reduces bandwidth and processing load on both the POP3 server and the client. The main application logic uses TopMessage to inspect message metadata (such as the Date header) to filter messages by age (sync_window_days) before deciding whether a full message download (GetMessage) is necessary. This avoids downloading large message bodies that are outside the desired sync window.
gmail.go - Gmail API Push Duplicate Prevention
The gmail.go package handles interactions with the Gmail API, specifically for pushing emails. It includes a critical safeguard to prevent duplicate messages from being inserted into a Gmail inbox.

## Gmail Message-ID Based Deduplication
Mechanism: Gmail API search for rfc822msgid.
Description: The PushEmail method in the gmail.Client implements a robust check to prevent pushing the same email to Gmail multiple times. This acts as a secondary layer of defense, complementing the POP3 UID tracking in the application's database.
Process:
When PushEmail is invoked with raw RFC2822 email bytes, it first attempts to parse the Message-ID header from the provided email content. The Message-ID is a globally unique identifier typically generated by the sending mail server.
If a Message-ID is successfully extracted, the method constructs a Gmail API search query in the format rfc822msgid:YOUR_MESSAGE_ID.
It then uses the c.lister.List("me").Q(q).MaxResults(1).Do() call to query the authenticated user's Gmail inbox. This search checks if a message with that specific Message-ID already exists in Gmail.
If the search returns any messages (i.e., len(res.Messages) > 0), it indicates that the email has already been successfully pushed to Gmail. In this scenario, PushEmail immediately returns nil (signifying success) without proceeding to make the actual Users.Messages.Import API call.
Benefit: This mechanism provides a strong guarantee against duplicate messages appearing in the Gmail inbox. Even if the application's local database tracking of POP3 UIDs were to be reset or corrupted, this Message-ID based check prevents the Gmail API from accepting and storing an email that it already contains, leveraging a standard and widely used email header for deduplication.
